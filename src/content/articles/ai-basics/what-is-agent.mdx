## 3行でいうと

1. AI が道具を使い、結果を見て次の手を自分で決めながら進む仕組み
2. 手順を人が決めておく「ワークフロー」とは、手順を誰が決めるかが違う
3. 手順が読めない仕事に向くが、時間と費用がかかり、まちがいも積み重なりうる

## たとえば

```text
あなた > テストが落ちている。直して
AI     → テストを動かす → 失敗の内容を読む → コードを直す
       → もう一度テストを動かす → 通るまで繰り返す → 報告する
```

- 何回繰り返すかを AI が結果を見て決めるので、これはエージェント
- 「テストを動かして、結果を要約して」と手順を決めて頼むなら、ワークフローに近い

## エージェントの基本の動き

```text
人の依頼
  ↓
┌→ 考える（次に何をするか決める）
│    ↓
│  道具を使う（検索、ファイル編集、コマンド実行など）
│    ↓
└─ 結果を見る（うまくいったか確かめる）
  ↓
終わったら報告する（迷ったら人に聞く）
```

- 考える、道具を使う、結果を見る、の3つを繰り返す
- 止まらなくならないよう、回数の上限などの止め方を決めておく

## ワークフローとの違い

|                  | ワークフロー             | エージェント             |
| ---------------- | ------------------------ | ------------------------ |
| 手順を決めるのは | 人（コードに書いておく） | AI（その場で決める）     |
| 向く仕事         | 手順が決まっている仕事   | 何手かかるか読めない仕事 |
| 結果のぶれ       | 小さい                   | 大きくなりうる           |
| 時間と費用       | 少ない                   | 多くなりやすい           |

Anthropic の解説では、両方をまとめて「エージェント的なシステム」と呼びます。そのうえで、手順を誰が決めるかで2つに分けています。

## どれを選ぶか

1. まず、AI に1回頼むだけで済まないか考える
2. 手順が決まっているなら、ワークフローにする
3. 手順が読めず、AI の判断に任せてよいときだけ、エージェントにする

<Callout type="warning">
  エージェントは自分で道具を動かすので、まちがいが積み重なることがあります。最初は、壊れても困らない場所で試してください。
</Callout>

## 身近な例

| 製品                         | エージェントとしての使われ方                 |
| ---------------------------- | -------------------------------------------- |
| Claude Code・Codex           | コードを読み、書き換え、テストを動かして直す |
| 各社の Agent SDK・Agents SDK | 自分のアプリにエージェントを組み込む         |

道具をつなぐ共通の決まりについては、[MCP とは](/ai-basics/what-is-mcp/)を参照してください。
