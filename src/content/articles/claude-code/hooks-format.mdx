## 3行でいうと

1. Hooks は、Claude Code の決まった場面で、自分のコマンドを必ず動かす仕組み
2. 「ファイルを書き換えたあと」に Prettier を動かせば、整形の頼み忘れがなくなる
3. 設定は `.claude/settings.json` に書き、`jq` で書き換えたファイルの名前を取り出す

## たとえば

```text
あなた      > src/sample.js に1行足して
Claude Code → ファイルを書き換える
Hooks       → 書き換えたファイルに Prettier を動かす（毎回、自動で）
```

- 所要時間：10分
- 用意するもの：Prettier が入ったプロジェクト、`jq` コマンド

## 1. 設定を書く

プロジェクトの `.claude/settings.json` に、次を足します。

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "f=$(jq -r '.tool_input.file_path') && npx prettier --write --ignore-unknown \"$f\""
          }
        ]
      }
    ]
  }
}
```

| 項目                            | 意味                                                  |
| ------------------------------- | ----------------------------------------------------- |
| `PostToolUse`                   | Claude Code が道具を使ったあとに動く                  |
| `matcher`                       | ファイルを書き換える道具（Edit・Write）のときだけ動く |
| `jq -r '.tool_input.file_path'` | 書き換えたファイルの名前を取り出す                    |

## 2. 試す

```text
> src/sample.js に、シングルクォートの文字列を1行足して
```

## 3. 動いたか確かめる

- 開いたファイルの `'...'` が `"..."` に変わっていれば動いている
- うまくいったときは、会話には何も表示されない

<Callout>
  Bash のコマンドで書き換えたファイルは、この設定では整形されません。必要なら FileChanged の Hooks
  を使います。
</Callout>

## 困ったとき

| 症状                         | 見るところ                                 |
| ---------------------------- | ------------------------------------------ |
| 何も変わらない               | `jq` が入っているか（`jq --version`）      |
| 一部のファイルだけ変わらない | Prettier が扱えない種類のファイルか        |
| 設定が読まれていない         | `/hooks` で、登録された Hooks の一覧を見る |
